# Maze Mind

AI Maze Runner with a Learning Layer — race the hunter, log every move,
let the data teach you.

One game that touches every lecture topic: a playable pygame maze runner
wired to a real ML pipeline. The player races an AI hunter through a
maze generated by randomized DFS under connectivity and path constraints;
every completed round is logged to SQLite; a separate ML
pipeline turns those logs into skill scores, playstyle clusters, and a
live win-probability meter; the predicted skill class feeds back into
the hunter's difficulty. The loop closes — this is integration, not two
projects glued together.

## Quickstart

```bash
# Python 3.12+ (validated locally on 3.14)
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.lock

# 1. Bootstrap training data (bot-simulated rounds — real play adds more later)
python main.py simulate --rounds-per-profile 120

# 2. Train all three models
python main.py train

# 3. Generate the report figures
python main.py dashboard

# 4. Start with Recruit: guided 8x8 maze, slow hunter, two-minute timer
python main.py play --tag yourname

# Switch to adaptive difficulty when you want a tougher chase
python main.py play --tag yourname --difficulty Adaptive

# Preserve your own maze dimensions and timer
python main.py play --tag yourname --difficulty Custom --width 9 --height 7 --time-limit 45 --seed 42

# Inspect your own history
python main.py records --tag yourname
```

Run the test suite any time with:

```bash
python -m pytest -q
```

## Notes for the report

- **CSP framing**: `game/maze_gen.py`'s module docstring states the
  variables/domains/constraints explicitly. The implementation constructs
  a spanning tree using randomized DFS backtracking; it is not a general
  CSP solver and does not sample spanning trees uniformly. The default
  path constraint requires 1.5 times Manhattan distance, capped for tiny
  grids. Generation raises an error if it cannot satisfy the constraint.
- **Why normalise**: `data/preprocess.py` docstring — KNN and K-Means are
  distance-based, so an unnormalised feature with a big numeric range
  would dominate Euclidean distance.
- **Difficulty without cheating**: `ml/knn_skill.py`'s `DIFFICULTY_BY_SKILL`
  only changes the hunter's re-plan/move cadence, never the search
  algorithm itself.
- Report figures are regenerated any time with `python main.py dashboard`
  into `dashboard/figures/`.

## Playing and difficulty

- Hold **WASD** or **arrow keys** to move smoothly down corridors. You can also
  use the on-screen pad or an adjacent-cell click. Pausing or leaving the window
  clears held movement so the player does not continue walking on return.
- **Recruit is the default:** an 8x8 maze, 120 seconds, an 8-second head start,
  a hunter that moves once every 2 seconds, and a persistent gold trail showing
  your next six steps. It includes three smokes, five radar charges, and a 3-second
  dash cooldown. Follow the gold trail toward the green exit.
- **Shift** dashes up to two cells; **F** stuns the hunter for 3 seconds and lets
  you walk or dash past it safely during that time;
  **R** shows the next eight route steps for 4 seconds.
- **P** or **Esc** pauses. Movement, abilities, cooldowns, and decision telemetry
  freeze while paused. Career records can be opened from the menu or pause screen.
- **Recruit**, **Runner**, and **Master** apply fixed presets. **Adaptive** tunes
  the hunter from recent skill history. After two consecutive losses it enables
  the gold guide, slows the hunter, adds smoke, and extends the timer to allow
  navigation. **Custom** preserves the supplied configuration. Switching presets
  does not overwrite the custom configuration.
- Without trained models the HUD displays **Model unavailable**. Successful
  and unsuccessful rounds open the results screen, including predicted playstyle.
  Closing or restarting an unfinished round does not create a completed-round record.
- Hunters start in a side corridor when one exists and detect players by corridor
  distance, so a nearby position behind walls does not trigger an immediate chase.
  The HUD shows exit progress prominently, with the model's estimate beneath it.

## Data and model reliability

Existing databases migrate automatically and retain their history. New telemetry
uses version 2: the game and bots share a clock, the hunter advances while bots
think, and pause time is excluded from decisions. Old telemetry remains visible
in records but is excluded from training with the new feature definitions.

`skill_label` holds ground truth with a `label_source` of `synthetic` or `verified`.
`predicted_skill`, `predicted_style`, and `model_version` store inference separately.
Human predictions never become training labels automatically. After independently
reviewing a round, you can supply a verified label:

```bash
python main.py label --round-id 12 --skill Intermediate
python main.py train
```

KNN fits its scaler inside each holdout/CV training split. Win-probability snapshots
are grouped by round when splitting; human snapshots are logged with the eventual
outcome and included during retraining. Metrics report synthetic and human results
separately; a missing human evaluation is reported as unavailable. Synthetic scores
do not establish accuracy on human players. Saved artifacts include metrics, their
training timestamp, and feature version. Final deployment models are refitted on
the full eligible dataset after evaluation.

Efficiency is net progress toward the exit divided by steps taken, bounded to
`[0, 1]`. For escaped rounds this equals optimal route length divided by steps.
Failed-round results show escape efficiency as `N/A`. Dashboard projections use
the saved model's scaler, so new data does not redefine the coordinate system.

To rebuild older or missing models, generate current telemetry and retrain:

```bash
python main.py simulate --rounds-per-profile 120
python main.py train
python main.py dashboard
```

Tests train temporary models and use temporary databases, including the UI's
menu, pause, history, win/loss screens, prediction caching, migrations, and split
boundaries. CI runs with dummy SDL video/audio drivers. `requirements.txt` lists
minimum dependencies; `requirements.lock` records the exact validated environment.
